# CHANGELOG

## 2026-10-09 (lock only from readiness, one school id)
- Lock: an ordinary failed request (network error, 502/503/504) is only a hint; it starts readiness probes (GET /api/health, 0.5s/1s backoff) and the app locks only after 3 consecutive failed probes. 4xx incl. 401/403 never count. Rollback: revert `services/serverHealth.js` (recordServerFailure/runProbes).
- School id: root cause of `schoolId=100093`: (a) `schoolInfo` state defaulted to the placeholder "100093" before login, (b) the 10 s requests poller captured a stale `refreshRequests` closure from that time, (c) many API helpers fell back to `localStorage.activeSchoolId` left by earlier logins. Now `services/session.js` `resolveSchoolId()` (token payload) is the single source for every school-scoped call in api.js and AppContext; a different explicit id from a single-school account is replaced and recorded (`getSchoolIdMismatches`). Placeholder defaults removed; schoolInfo.schoolId cleared on logout.
- Requests poller: uses a ref to the latest function, stops on 401/403, backs off 10s->60s on transient errors, shows the shared notice once (action "Requests refresh").
- Copy-error report: title follows the action (Server Health Check / Draft Save / ...); school id from the session; tokens/secrets scrubbed (tested).
- Tests: serverHealth rewritten for probe-based locking; sessionSchool, report-title and e2e (stale school id, single Failed to fetch, 403 no loop).

- Fix (data loss): edits vanishing after logout/login. Causes found: (1) `PUT /api/school/draft` answered "success" from a per-worker in-memory/Redis buffer BEFORE the database write, so DB failures, worker restarts and out-of-order requests across PM2 workers silently lost or reverted data; (2) `GET /draft` was served from a per-worker cache that could be stale right after login; (3) logout cleared the session without flushing the 3.5 s auto-save debounce; (4) login compared client clocks (many school PCs are wrong) to choose local vs cloud draft; (5) auto-save aborted in-flight saves and could run after a failed/partial initial load.

Removed `activeDraftAbortController` entirely. Tests: `node --test client/tests/draftSaver.test.mjs`, `node --test server/tests/draft_save_route.test.js`. Read-only recovery report: `node server/scripts/find_affected_drafts.js`.

- Feature: app-wide server-health lock. `fetchWithAuth` (api.js) reports 502/503/504, network failures and 60s timeouts to `services/serverHealth.js`; 2 consecutive failures within 30s lock the app (4xx never counts). ## 2026-09-09
- Feature: Personnel Profiling → Education tab's "Educational Attainment" section now supports multiple degree entries (College Degree, Major, Minor) via a repeatable "+ Add Degree" list, matching the existing NEAP Trainings pattern, instead of a single static degree/major/minor field set. - Perf: Executive Dashboard (`GET /api/dashboard/stats`) no longer opens a brand-new `pg.Pool` (and tears it down) for the `insightEd` cross-database fallback on every request — the pool is now created once and reused. This was adding a full extra DB connection round trip to every dashboard load. The two remaining fallback queries against that pool (master personnel merge, school identity lookup) are also now run with `Promise.all` instead of sequential `await`s where they were independent.
- Fix: Weekly Schedule Editor — grade-band filtering for subject/section pairing now applies in both block-creation flows. (1) Block Inspector's "Class Section & Grade Level" dropdown filters to only sections whose grade level actually offers the currently selected Subject (per `MASTER_SUBJECTS_CATALOG`). (2) The docked sidebar's "Organized Classes at This School" list (used by the drag-first flow, where a subject is picked from "Subjects Taught" first and a section is then dragged onto the Gantt chart) applies the same filter. Previously an invalid subject/grade pairing (e.g. "Reading and Literacy" on a Grade 2 section) could be selected/dragged in either flow and was only caught after the fact by the MATATAG policy warning; it's now unselectable in the UI in both places. If no subject is selected yet, all sections still show as before.
