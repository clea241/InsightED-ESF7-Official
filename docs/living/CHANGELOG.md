# CHANGELOG

## 2026-09-09
- Feature: Personnel Profiling → Education tab's "Educational Attainment" section now supports multiple degree entries (College Degree, Major, Minor) via a repeatable "+ Add Degree" list, matching the existing NEAP Trainings pattern, instead of a single static degree/major/minor field set. Data model: `collegeDegree`/`major`/`minor` single fields replaced by `degreeRows: [{ collegeDegree, major, minor }]` on the personnel record (legacy single fields are still read as a fallback for older records). "Highest Educational Attainment" remains a single top-level field.
- Perf: Executive Dashboard (`GET /api/dashboard/stats`) no longer opens a brand-new `pg.Pool` (and tears it down) for the `insightEd` cross-database fallback on every request — the pool is now created once and reused. This was adding a full extra DB connection round trip to every dashboard load. The two remaining fallback queries against that pool (master personnel merge, school identity lookup) are also now run with `Promise.all` instead of sequential `await`s where they were independent.
- Fix: Weekly Schedule Editor — grade-band filtering for subject/section pairing now applies in both block-creation flows. (1) Block Inspector's "Class Section & Grade Level" dropdown filters to only sections whose grade level actually offers the currently selected Subject (per `MASTER_SUBJECTS_CATALOG`). (2) The docked sidebar's "Organized Classes at This School" list (used by the drag-first flow, where a subject is picked from "Subjects Taught" first and a section is then dragged onto the Gantt chart) applies the same filter. Previously an invalid subject/grade pairing (e.g. "Reading and Literacy" on a Grade 2 section) could be selected/dragged in either flow and was only caught after the fact by the MATATAG policy warning; it's now unselectable in the UI in both places. If no subject is selected yet, all sections still show as before.
