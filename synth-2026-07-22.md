# CODEBASE ARCHITECTURE SNAPSHOT — ESF7 PLATFORM

## 0. Overview
- **Stack**: Full-Stack Node.js / React (Vite) / Express / PostgreSQL
- **Runtime**: Node.js 18+
- **Architecture Pattern**: Decoupled Client-Server (REST API), Controller-Service DB layer, Background Queue Worker Threads
- **Entry Points**:
  - Backend: `server/server.js`
  - Frontend: `client/src/main.jsx`, `client/src/App.jsx`
  - Queue Worker: `server/queue_worker.js`
- **Configuration Files**: `server/.env`, `client/vite.config.js`, `ecosystem.config.js`

## A. Database & Schema Layer

### 1. `schools`
- `id`: PRIMARY KEY (SERIAL)
- `school_id`: VARCHAR(50) UNIQUE NOT NULL (DepEd School ID)
- `school_name`: VARCHAR(255) NOT NULL
- `region`: VARCHAR(100), `division`: VARCHAR(100), `district`: VARCHAR(100)
- `school_year`: VARCHAR(50) (e.g. "SY 2026-2027")
- `number_of_shifts`: INT DEFAULT 1
- `curricular_offering`: TEXT[] (Array of levels: Elementary, JHS, SHS)
- `created_at`: TIMESTAMP DEFAULT CURRENT_TIMESTAMP

### 2. `personnel`
- `id`: PRIMARY KEY (SERIAL)
- `school_id`: INT REFERENCES `schools(id)` ON DELETE CASCADE
- `employee_id`: VARCHAR(50) UNIQUE (DepEd Employee Number)
- `first_name`: VARCHAR(100), `middle_name`: VARCHAR(100), `last_name`: VARCHAR(100), `extension_name`: VARCHAR(20)
- `sex`: VARCHAR(20), `fund_source`: VARCHAR(100), `employment_status`: VARCHAR(100)
- `created_at`: TIMESTAMP DEFAULT CURRENT_TIMESTAMP

### 3. `personnel_employment`
- `id`: PRIMARY KEY (SERIAL)
- `personnel_id`: INT REFERENCES `personnel(id)` ON DELETE CASCADE UNIQUE
- `position_title`: VARCHAR(150), `salary_grade`: INT, `step_number`: INT, `basic_salary`: NUMERIC(10,2)
- `appointment_date`: DATE, `first_entry_date`: DATE

### 4. `personnel_qualifications`
- `id`: PRIMARY KEY (SERIAL)
- `personnel_id`: INT REFERENCES `personnel(id)` ON DELETE CASCADE
- `degree`: VARCHAR(255), `major_specialization`: VARCHAR(255), `minor_specialization`: VARCHAR(255)
- `civil_service_eligibility`: VARCHAR(255)

### 5. `personnel_trainings`
- `id`: PRIMARY KEY (SERIAL)
- `personnel_id`: INT REFERENCES `personnel(id)` ON DELETE CASCADE
- `title`: VARCHAR(255), `hours`: INT, `category`: VARCHAR(100), `date_attended`: DATE

### 6. `class_sections`
- `id`: PRIMARY KEY (SERIAL)
- `school_id`: INT REFERENCES `schools(id)` ON DELETE CASCADE
- `grade_level`: VARCHAR(50), `section_name`: VARCHAR(100), `advisor_id`: INT REFERENCES `personnel(id)`

### 7. `workload_rows`
- `id`: PRIMARY KEY (SERIAL)
- `personnel_id`: INT REFERENCES `personnel(id)` ON DELETE CASCADE
- `subject_name`: VARCHAR(150), `grade_level`: VARCHAR(50), `section_name`: VARCHAR(100)
- `minutes_per_week`: INT, `teaching_type`: VARCHAR(50)

### 8. `submissions` & `submission_queue`
- Track eSF7 Excel/XLSB export generation jobs, queue status (`pending`, `processing`, `completed`, `failed`), and output file paths.

## D. UI Interaction / Data Flow Matrix

1. **Add Personnel**:
   `PersonnelMasterlist.jsx` [Add Personnel Button] -> Form Modal -> `POST /api/personnel` -> DB `personnel` table -> Masterlist State Update.

2. **Update Qualifications**:
   `PersonnelProfile.jsx` [Qualifications Tab -> Save] -> `POST /api/qualifications` -> DB `personnel_qualifications` table -> Refetch Profile.

3. **Generate eSF7 Official Export**:
   `Submission.jsx` [Generate Form 7] -> `POST /api/reports/generate-esf7` -> Queue Worker (`queue_worker.js` + `esf7_xlsb.js`) -> XLSB artifact generated in `server/scratch/` -> Download Link.

## F. Antigravity AI Engineering & Reconstruction Workflow

*(Synthesized from `Planning ESF7 Platform Reconstruction.md`)*

### 1. Non-Blocking Event Loop Architecture
During the platform reconstruction documented in `Planning ESF7 Platform Reconstruction.md`, a primary performance bottleneck was identified where heavy CPU operations (such as binary XLSB parsing and report generation using `xlsx`) blocked Node's single-threaded event loop, leading to HTTP request timeouts (`504 Gateway Timeout`).
- **Solution**: Antigravity offloaded CPU-heavy jobs to dedicated **Node.js Worker Threads** (`esf7_worker_thread.js`).
- **Result**: Main Express endpoints (`GET /api/school`) remain instantly responsive (~61ms response times) even while 15MB+ Excel files are being generated concurrently in background worker threads.

### 2. Autonomous Empirical Verification
Antigravity operates with strict verification loops:
- Every code edit is verified using empirical test commands (e.g. `Invoke-WebRequest`, concurrent benchmark scripts, or Node syntax checks) before declaring success.
- Stack traces and runtime logs are parsed silently and thoroughly before forming diagnostic hypotheses.

### 3. Progressive Database & Queue Migration
- Shifted legacy unstructured state into normalized PostgreSQL schemas (`schools`, `personnel`, `personnel_employment`, `personnel_qualifications`, `workload_rows`).
- Implemented an asynchronous background submission queue (`queue_worker.js` and `submission_queue` table) to prevent browser UI hanging during long-running exports.

### 4. Continuous Learning & Self-Containment (`.agents/`)
- All architectural decisions, DepEd ESF7 rules, and user preferences are recorded in `.agents/memory/` and `synth-2026-07-22.md`.
- Antigravity uses this memory context on every task to avoid repeating past bugs or re-asking previously answered domain questions.
