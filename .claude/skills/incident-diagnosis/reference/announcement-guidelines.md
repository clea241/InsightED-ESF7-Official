# Announcement guidelines

Rules for `announcement-draft.md` (generated by `build-incident-report.js` from the `announcement` block of `investigation.json`).

1. **Apologise for known losses.** Name what was lost in plain words ("class sections you entered on 15 October"), not systems.
2. **Say plainly what happened and what changed.** One or two short sentences each. Only confirmed facts.
3. **Tell users exactly what to do.** Re-enter specific data, log in again, check a specific page. If nothing is needed, say so.
4. **One-time logout.** If `JWT_SECRET` was rotated, say users will be logged out once and should log in again.
5. **Do not promise the data is safe** until confirmed (`dataSafeConfirmed: true` only after a query or backup comparison). Until then say what is still being checked.
6. **Do not speculate about cause.** If the cause is not confirmed, describe the effect and what is being done.
7. **No jargon, no blame.** No server names, error codes, or people. Refer to "an update" or "a problem with saving", not commits or individuals.
8. **State what is still being checked and when the next update comes.**
9. **Two lengths.** A short version for chat (3-5 sentences) and a longer one for email.
10. **Unknown facts appear as `UNKNOWN: ...`** for the user to fill in before sending. Never delete an UNKNOWN by guessing.
11. **Privacy.** No names, emails, phone numbers, school-specific data, or IPs. Affected schools are told individually by the user using `affected-ids.csv`, not named in a broadcast.
12. **Also send the holding message** (`holding-message.md`) as soon as the incident is known; it is the first communication, the announcement is the second.
